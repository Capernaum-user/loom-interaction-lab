오디오 파일을 쓰지 않는다. 진동자 하나와 감쇠 곡선 하나면 신호음이 된다.

파형

        

          
          
회색은 계산한 파형(진동자 × 감쇠), 파란색은 지금 실제로 나가고 있는 소리를 분석기로 읽은 것이다.
          소리를 한 번 눌러야 파란 선이 나타난다.

        

      

    


    
// 오실레이터 1개 + 지수 감쇠. 이게 전부다.
function blip(freq, dur, type, vol, glide){
  const o = ctx.createOscillator(), g = ctx.createGain(), t = ctx.currentTime;
  o.type = type; o.frequency.setValueAtTime(freq, t);
  if (glide) o.frequency.exponentialRampToValueAtTime(freq * glide, t + dur);
  g.gain.setValueAtTime(0.0001, t);
  g.gain.exponentialRampToValueAtTime(vol,    t + 0.008);  // 8ms 어택
  g.gain.exponentialRampToValueAtTime(0.0001, t + dur);    // 지수 감쇠
  o.connect(g); g.connect(ctx.destination);
  o.start(t); o.stop(t + dur + 0.02);
}

    
exponentialRampToValueAtTime은 0을 받지 못한다. 그래서 0.0001에서 시작하고 0.0001로 끝난다.
    0을 넣으면 소리가 나지 않고 콘솔에 오류가 남는다. 이 한 줄이 WebAudio 신호음에서 가장 자주 나오는 실수다.

궤적

        

          
          
가로는 시간, 세로는 위치다. 파란 선이 1.0을 넘어갔다 되돌아오면 그게 튕김이다.
          감쇠를 낮추면 여러 번 흔들리고, 높이면 넘어가지 않고 눌러앉는다. 회색 베지에는 무슨 값을 줘도 넘지 않는다.

        

      

    


    
감쇠비가 1을 넘으면(과감쇠) 스프링은 튕기지 않는다. 그때는 베지에와 구별이 거의 안 되니 굳이 물리를 돌릴 이유가 없다.
    스프링을 쓸 값어치는 손가락이 만든 속도를 그대로 이어받을 때 생긴다. 놓는 순간의 속도를 초기 속도로 넣으면 화면이 손을 기억한 것처럼 움직인다.

  


  


  

    
여기 쓰인 소리·그림·움직임은 전부 이 파일 안에서 계산해 만든다. 원본 도구의 SVG·WAV·서체를 내려받아 쓰지 않았고,
    그 사이트가 크롤을 막아 둔 경로도 열지 않았다. 기법은 누구나 다시 만들 수 있지만 자산은 만든 사람의 것이라 그렇게 나눴다.
